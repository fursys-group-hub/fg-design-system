# flow-check 검사 항목 모음

화면이 **실제 상황을 견디는지** 보는 항목을 모아둔다.
design-qa 가 규칙 준수(색·크기·마크업)를 본다면, flow-check 는 **데이터가 있을 때만 그려진 화면이 아닌지**를 본다.
새 문제가 나오면 여기에 한 줄 추가한다. 항목이 늘어도 스킬(`flow-check/SKILL.md`)은 건드리지 않는다.

## 기계가 잡을 수 있는 것

| 항목 | 무엇을 보는가 |
|---|---|
| 빈 목록 문구 | 목록이나 표에 데이터가 0건일 때 보여줄 문구(빈 상태)가 있는지. 없으면 위반 |
| 인풋 오류 상태 | 인풋에 오류 상태 표시와 안내 문구가 있는지. 없으면 위반 |
| 대기 자리 표시 | 데이터를 기다리는 동안 보여줄 자리 표시(스켈레톤·플레이스홀더)가 있는지 |
| 결과 알림 자리 | 저장이나 삭제 뒤 결과를 알려주는 자리(토스트 등)가 있는지 |
| 긴 텍스트 처리 | 표 밖의 긴 텍스트에 줄바꿈이나 말줄임(ellipsis) 처리가 있는지 |

## 사람이 봐야 하는 것

| 항목 | 무엇을 보는가 |
|---|---|
| 상세 화면 유무 | 목록만 있고 상세 화면이 없는지 |
| 수정·삭제 유무 | 등록만 있고 수정이나 삭제가 없는지 |
| 되돌릴 수 없는 동작 확인 | 되돌릴 수 없는 동작(삭제 등)에 확인 단계가 있는지 |
| 이동 경로 단절 | 화면 사이 이동 경로가 끊긴 곳이 없는지 |

## 아직 정본에 규칙이 없는 것

| 항목 | 무엇을 보는가 |
|---|---|
| 로딩 상태 | 로딩 상태는 정본에 규칙이 없으므로 경고로만 알린다. Loader 아이콘 3종이 있으나 사용 규칙이 정해지지 않았다 |
