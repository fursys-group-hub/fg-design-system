# status — 저장소 상태와 남은 일 한 번에 파악

새 세션에서 매번 반복하던 확인(브랜치·변경·최근 커밋·두 벌 어긋남·미정 표시)을 한 번에 읽어 보고하는 읽기 전용 워크플로우.

## design-qa · flow-check 와 무엇이 다른가

- **design-qa / flow-check 는 화면 HTML 파일 하나**를 검사한다(규격 준수 / 실제 상황 견딤).
- **status 는 저장소 전체의 상태**를 본다. 화면을 검사하는 게 아니라 "지금 이 저장소가 어떤 상태이고 무엇이 남았나"를 파악한다. 대상 파일을 받지 않는다.

## 원칙 (필수)

- **아무것도 고치지 않는다. 읽기와 보고만 한다.** 파일 수정·스테이징·커밋·푸시를 하지 않는다(이 스킬 자체의 결과를 커밋하지도 않는다).
- **문제를 만들어내지 않는다.** 항목이 깨끗하면 "없음"으로 명확히 말한다. 억지로 지적거리를 찾지 않는다.
- 값을 추정하지 않는다. 각 항목은 실제 명령(`git ...`, `grep -n`, `diff`)의 출력으로 판정한다.
- 판단이 애매하면 지어내지 말고 `[확인 필요]`로 표시한다.

## 보고할 여섯 가지

### 1. 현재 브랜치와 origin 차이

- `git status -sb` 첫 줄, 또는 `git rev-list --left-right --count origin/main...HEAD` 로 **ahead / behind 개수**를 읽는다.
- `현재 브랜치 · origin/<branch> 대비 ahead N · behind M` 형식으로 보고한다. 0/0 이면 "동기화됨".

### 2. 커밋 안 된 변경

- `git status --short` 로 변경 파일 목록을 읽는다.
- **각 파일마다 무슨 성격의 변경인지 한 줄**로 요약한다(파일 경로·확장자·`git diff --stat` 로 대략 파악). 예: "문서 문구 수정", "CSS 셀렉터 변경", "새 스킬 파일".
- 없으면 "작업 트리 깨끗".

### 3. 최근 커밋 다섯 개

- `git log -5 --pretty=format:'%h %s'` 로 **첫 줄(제목)만** 목록으로 보여준다.

### 4. design-system ↔ dist/fg 두 벌 어긋남 (가장 위험한 지점)

- 이 저장소는 정본(`design-system/`)과 배포물(`dist/fg/`) **두 벌을 같이 유지**한다. 같은 이름 파일이 어긋나면 여기서 티가 나므로 **가장 위험한 지점**이다.
- 두 폴더에 **같은 basename 으로 존재하는 파일**을 찾아 하나씩 내용 비교한다. 예: `fg-components.css` · `COMPONENTS.html` · `component-spec.md` · `design-principles.md` · `layouts.md` · `icons.md` · `CLAUDE.md` · `CLAUDE-customer.md` · `fg-customer.css`.
  - **비교 전에 dist/fg 판 맨 위 배포 배너를 제외한다.** `design-principles.md`·`layouts.md`·`icons.md` 의 dist/fg 판에는 맨 위에 **배포 배너**(`배포물(관리자 수기 유지)` HTML 주석 + `버전 / 생성 커밋` 줄 + 뒤따르는 빈 줄)가 있다. 이 배너는 **의도적으로 dist 판에만** 있는 헤더라 정본에는 없다. 걷어내지 않으면 diff 가 항상 뜨지만 **어긋남이 아니다.** 예: `diff <(sed '/^<!-- 배포물/,/^$/d' dist/fg/<f>) design-system/<f>` 로 배너 블록을 제외하고 본다. **제외한 줄 수를 보고에 적는다**(현재 각 파일 4줄).
  - `diff -q design-system/<f> dist/fg/<f>` (또는 `git diff --no-index`) 로 **다른지만** 먼저 본다.
  - 다르면 그 파일을 표시하고, 어디가 다른지 몇 줄로 요약한다. `[확인 필요]`: 두 벌이 **의도적으로 다른 파일**(예: 루트 `CLAUDE.md` 는 별개, `Design.md`·`README.md`·`tokens.css` 는 `dist/fg` 에만, `index.md`·`extraction-plan.md`·`tokens/` 는 `design-system` 에만)은 비교 대상이 아니다. **양쪽에 같은 이름으로 있고 같아야 하는 파일만** 본다.
- 전부 일치하면 "두 벌 일치".

### 5. 문서에 남은 미정 표시

- `[확인 필요]` · `미정` · `TODO` · `보류` 를 문서에서 찾는다(`grep -rn`).
- **제외**: `_deprecated/` 폴더, 과거 이력 문서(`extraction-plan.md`, `audits/qa-self-*.md` 등), 그리고 이 표시어를 **설명·규칙으로** 언급하는 줄(예: "불확실하면 `[확인 필요]` 로 표시한다" 같은 지침 문장)과 마이그레이션 메모(`design-qa-checklist.md` 의 "스킬 자체에서 고쳐야 할 옛 기준"은 6번에서 따로 본다).
- 남은 실질 미정 항목을 **파일·줄·내용**으로 보여준다. 없으면 "남은 미정 없음".

### 6. 옛 기준 잔여 (design-qa-checklist.md)

- `design-system/audits/design-qa-checklist.md` 의 **"스킬 자체에서 고쳐야 할 옛 기준"** 섹션 표를 읽는다.
- 이 표는 스킬을 최신으로 유지하려는 마이그레이션 메모다. 각 행에는 **상태 열**이 있고, 반영된 행에는 커밋 해시가, 아직 안 된 행은 비어 있다.
- **상태 열이 빈 행만** 잔여로 세어 목록으로 보여준다(무엇을 무엇으로 바꿔야 하는지). 해시가 적힌 행은 이미 반영됐으므로 잔여로 세지 않는다. 빈 행이 없으면 "옛 기준 잔여 없음".

## 보고 형식

여섯 항목을 **번호 순서대로** 표나 목록으로 정리해 보여준다.

- 1·3 은 짧은 목록, 2·4·5·6 은 표(파일 / 내용) 또는 목록.
- 각 항목은 **깨끗하면 "없음"** 으로 명확히 닫는다. 문제를 부풀리지 않는다.
- 맨 아래 **한 줄 요약**: `ahead N/behind M · 미커밋 K개 · 두 벌 어긋남 X개 · 미정 Y개 · 옛 기준 Z개`. 전부 0이면 **"clean — 시작하기 좋음"**.

## 하지 않는 것

- 파일을 고치지 않는다. 스테이징·커밋·푸시하지 않는다.
- 발견한 문제를 이 스킬이 대신 고치지 않는다. 보고만 하고, 고칠지는 사용자가 정한다.
