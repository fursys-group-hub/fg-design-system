# design — 화면 제작 진입점

담당자가 퍼시스그룹 디자인 시스템 정본으로 화면을 만드는 5단계 워크플로우. 양식을 복사해 채우던 과정을 대체한다. **구조 → 내용 → 모양** 순서를 강제한다.

> ## ⚠️ 절대 규칙 (예외 없음)
> 1. **이 저장소의 파일을 절대 수정하지 않는다. 읽기만 한다.** 정본(`design-system/`·`dist/fg/`)은 참조용이다. 여기에 화면을 만들거나 값을 고치지 않는다.
> 2. **만든 화면은 반드시 이 저장소 폴더 밖에 저장한다.** 기본값은 `~/Desktop/fg-output` 이다. 저장소 안 경로가 나오면 거부하고 다시 묻는다.
> 3. **색은 `tokens.css` 변수만, 글자는 정의된 타이포 17종만, 여백은 spacing 스케일만** 쓴다. hex·임의 `font-size`·임의 px 여백을 직접 쓰지 않는다. 필요한 값이 없으면 지어내지 말고 관리자에게 알린다.

---

## 진행 순서 (5단계)

### 1단계 — 브랜드를 묻는다

아홉 개 중 하나를 고르게 한다(`<html data-brand="...">` 에 슬러그를 넣는다). Primary 2톤(600/200)만 브랜드마다 다르고, System·Grey 는 9브랜드 공통이다.

| 브랜드 | 슬러그 |
|---|---|
| 시디즈 | `sidiz` |
| 퍼시스 | `fursys` |
| 일룸 | `iloom` |
| 데스커 | `desker` |
| 알로소 | `alloso` |
| 슬로우베드 | `sloubed` |
| 레터스 | `letus` |
| 퍼플식스 | `p6` |
| 그룹사 공통(기본) | `group` |

### 2단계 — 화면 유형을 묻는다

두 유형 중 하나를 고르게 한다. `<html>` 태그에 유형을 표시한다(`data-type`).

- **업무 화면** (`data-type="internal"`) — 관리자 콘솔·OMS 류 사내 관리 화면. 정보 밀도가 높고 데스크톱 전용이다.
- **고객 화면** (`data-type="customer"`) — 랜딩·브랜드·프로모션 등 고객이 보는 화면. 타이포 위계가 크고 반응형(≤768)을 지원한다.

유형에 따라 읽는 정본 문서와 CSS 가 다르다(아래 「읽어야 하는 정본」 참조). 유형을 말하지 않으면 추측하지 말고 물어본다.

### 3단계 — 무엇을 만들지 묻는다

화면의 **목적**, 담아야 할 **정보**, 필요한 **기능**을 물어본다.
**디자인 값(색·크기·여백)은 묻지 않는다.** 그건 정본에 있다. 담당자에게 물을 것은 "무엇을/왜"이지 "몇 px"이 아니다.

### 4단계 — 계획을 먼저 보여주고 확인을 받는다 (핵심)

파일을 만들기 전에 **화면 계획**을 세 칸 표로 보여준다. 어떤 영역이 어떤 순서로 들어가고 어느 컴포넌트를 쓰는지다.

| 화면(영역) | 구성 | 컴포넌트 |
|---|---|---|
| (예) 페이지 헤더 | 페이지 타이틀 + 우측 브레드크럼 | `.fg-*` 타이틀·브레드크럼 |
| (예) 필터 | 검색 필터 카드 | `.fg-filter` 등 |
| … | … | … |

- **사용자가 확인하기 전에는 파일을 만들지 않는다.**
- 바로 만들면 다 만든 뒤에 구조를 바꾸게 되고, 그러면 맞춰놓은 모양이 다시 흐트러진다. 그래서 구조를 먼저 합의한다.
- 계획은 정본의 골격·조립 순서를 따른다(업무=`layouts.md`·`design-principles.md`, 고객=`CLAUDE-customer.md` 「골격 순서」).

### 5단계 — 확인을 받으면 만든다

1. **저장 위치를 묻는다.** 기본값은 `~/Desktop/fg-output` 이다. 폴더가 없으면 만든다.
   - **저장소 안(`fg-design-system/` 하위) 경로면 거부하고 다시 묻는다.** 절대 규칙 2.
2. 정본 마크업을 **복사해 조립**하고 텍스트만 바꾼다. 구조·클래스명·중첩·아이콘 위치를 바꾸지 않는다(업무 화면은 `COMPONENTS.html` 이 마크업 정본).
3. `<html data-brand="..." data-type="...">` 를 정확히 표시한다. Pretendard 웹폰트 로드 1줄과, 인터랙션이 필요한 화면은 `COMPONENTS.html` 하단 `<script>` 블록을 함께 넣는다.
4. **만든 뒤 `design-qa` 를 이어서 실행**해 검사 결과까지 보여준다. 위반이 있으면 저장한 화면 파일만 고치고 정본은 건드리지 않는다.

## 읽어야 하는 정본 (유형별)

만들기 전에 해당 문서를 **읽고** 그 기준을 따른다. 값을 외워서 쓰지 않는다.

### 공통 (두 유형 모두)
- `dist/fg/tokens.css` — 색·타이포 변수와 타이포 17종 클래스. 모든 값의 출처.
- `CLAUDE.md`(루트) — 저장 위치·절대 원칙·유형 구분 규칙.

### 업무 화면 (`internal`)
우선순위 순서: **`COMPONENTS.html` → `fg-components.css` → `tokens.css` → `component-spec.md` → `layouts.md`**.
- `dist/fg/CLAUDE.md` — 업무 화면 규칙의 정본(색·타이포·컴포넌트·상태 5범주·표 구조·인터랙션).
- `dist/fg/COMPONENTS.html` — 마크업 정본. 복사해 조립할 원본.
- `dist/fg/fg-components.css` — 컴포넌트 CSS 정본(수정 금지).
- `dist/fg/Design.md` — 값·규격 통합 규격서.
- `dist/fg/design-principles.md` — 화면 조립·판단 기준.
- `dist/fg/component-spec.md` — 피그마 실측 수치 원장.
- `dist/fg/layouts.md` — 화면 유형별 골격·배치 순서·반응형(업무는 데스크톱 전용).

### 고객 화면 (`customer`)
- `dist/fg/CLAUDE-customer.md` — 고객 화면 규칙의 정본(설계/디자인 경계·골격 순서·키비주얼·타이포 매핑·모바일 축소·색 비중).
- `dist/fg/fg-customer.css` — 고객 화면 골격 CSS(색·타이포 토큰은 `tokens.css` 와 함께 로드).
- 반응형은 `@media (max-width: 768px)` 하나만 쓴다. 새 브레이크포인트를 만들지 않는다.

> 값이 서로 다르면 정본이 우선한다. `Design.md` 요약과 `tokens.css`·`CLAUDE.md` 가 어긋나면 후자가 우선이다.

## 하지 않는 것

- 정본 파일을 고치지 않는다(읽기 전용).
- 저장소 안에 결과물을 만들지 않는다.
- 정본에 없는 색·크기·여백·컴포넌트를 지어내지 않는다. 없으면 관리자에게 알린다.
- 계획 확인 전에 파일을 만들지 않는다.
